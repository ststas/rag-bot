# Проектная работа 7 спринта: кейс «QuantumForge Software»

## Задание 1. Исследование моделей и инфраструктуры

Подробное сравнение с таблицами и источниками: [Task1/task1.md](Task1/task1.md).

### Выбор

| Что | Решение |
| --- | --- |
| Сервер | вариант M на EC2: `g6e.xlarge` (1× NVIDIA L40S, 48 ГБ; 4 vCPU; 32 ГиБ RAM), AWS Франкфурт, ≈ $1 713 в месяц с диском. Вариант S (`g6.xlarge`, ≈ $744) как пилот при условии проверки качества |
| LLM | локальная модель класса 27–33B: Qwen3.8-27B, Muse-Glimmer-30B или gemma-4-31B-it (по собранным данным одного уровня; конкретную выбираем при построении бота) |
| Эмбеддинги | локальные: Qwen3-Embedding-0.6B (запасной вариант bge-m3) |
| Векторная БД | ChromaDB |

### Почему так

- **Конфиденциальность.** В задании сказано, что часть материалов может быть конфиденциальной и не должна уходить в облако (в описании компании есть подготовка к SOC 2 и PDF-спецификации заказных проектов). Поэтому LLM и эмбеддинги локальные, данные остаются в аккаунте компании.
- **Векторная БД.** ChromaDB хранит метаданные, фильтрует по полям (разделы Confluence, типы документов, даты), поддерживает обновление и удаление (прирост ≈ 400 страниц в месяц). У FAISS метаданных нет, фильтр только по id, отдельной операции обновления нет.
- **Размер сервера.** M опирается на собранные данные по моделям класса 27–33B. L (≈ $4 229 в месяц) для чат-бота по документам избыточен. S дешевле, но данных о качестве моделей 7–8B в источниках нет. SageMaker на том же инстансе дороже на 35%, имеет смысл при отсутствии команды сопровождения инфраструктуры.
- **Для кого.** Заказчик — QuantumForge Software: сократить время поиска информации и нагрузку на старших разработчиков и поддержку, упростить подготовку к SOC 2. Пользователи — разработчики, поддержка, менеджеры и аналитики, новые сотрудники.

### Не проверено

Качество моделей размеров S и L, скорость, нагрузка (число пользователей и запросов), язык документации, схема обработки PDF.

## Задание 3. Векторный индекс базы знаний

| Параметр | Значение |
|---|---|
| Модель эмбеддингов | [Qwen3-Embedding-0.6B](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B), локально через `sentence-transformers` |
| Размер эмбеддинга | 1024 |
| База знаний | [Task2/knowledge_base/](Task2/knowledge_base/): 41 документ, 6 295 слов |
| Векторная БД | ChromaDB, косинусное расстояние, [Task3/chroma_db/](Task3/chroma_db/) |
| Чанков в индексе | 59 |
| Время генерации эмбеддингов | 4,9 с (59 чанков, батч 16, Apple Silicon) |

Чанки делит `RecursiveCharacterTextSplitter` из LangChain: 150 слов с перекрытием 10% (15 слов), длина считается в словах. Документы короткие (97–246 слов, медиана 139), поэтому размер взят меньше 200: так часть документов делится на несколько чанков, как это будет с большими документами. К каждому чанку сохранены путь к файлу, заголовок, номер чанка, число чанков в документе и позиция начала в тексте.

Проверка качества: три запроса, результаты в [Task3/search_example.md](Task3/search_example.md). На «Что случилось на суде над Радием?» и «Кто такой Верховин?» первым найден нужный документ. На «Кто убил Корвина Арсеновича?» первым найден документ об убийстве, а второй и третий результат — дом и слуга, из-за общих имён.

## Задание 4. RAG-бот с Few-shot и Chain-of-Thought

Бот собран без готовой цепочки RetrievalQA: каждый шаг написан отдельно в [Task4/rag.py](Task4/rag.py).

| Шаг | Реализация |
|---|---|
| Запрос и поиск | тот же Qwen3-Embedding-0.6B, запрос кодируется с `prompt_name="query"`, в ChromaDB берутся 4 ближайших чанка |
| Пустой результат | если ближайший чанк дальше порога 0.5 (косинусное расстояние), бот отвечает «Я не знаю» без вызова LLM; в проверке релевантные чанки были на расстоянии 0.27–0.38, нерелевантные 0.65–0.76 |
| Промпт | system-сообщение с правилом отвечать только по фрагментам, затем 2 примера Few-shot, затем фрагменты с именем файла и вопрос |
| Few-shot | два примера из нашей базы (документ `pylnikov.md`): один с ответом, один с отказом «Я не знаю» |
| Chain-of-Thought | system-промпт «сначала размышляет, а потом отвечает, всегда пиши свои шаги»; ответ состоит из пронумерованных шагов и строки «Ответ: …» |
| LLM | `gemma4:e2b-mlx` в Ollama на хосте (`/api/chat`, температура 0, `think=false`); имя модели берётся из `LLM_MODEL` в файле `.env` (образец — `.env.example`), адрес Ollama из `OLLAMA_URL` |
| Окно модели | перед отправкой оценивается размер промпта (по 2,5 символа на токен, с запасом) и сравнивается с окном модели из Ollama (`/api/show`, у `gemma4:e2b-mlx` 131 072 токена) за вычетом 1 024 токенов под ответ; если не помещается, убираются самые дальние чанки, и бот сообщает об этом. Реальный промпт сейчас около 1 600 токенов, оценка даёт около 2 000. Значения можно задать переменными `MAX_CONTEXT` и `ANSWER_RESERVE` |
| Интерфейс | консольный REPL |

Запуск бота описан в разделе «Запуск в Docker» ниже.

Примеры диалогов в [Task4/dialogs.md](Task4/dialogs.md): 5 успешных ответов, 2 отказа (один по порогу расстояния, один от модели) и 2 ложных отказа маленькой модели. Ярлыки в файле проставляются автоматически по результату запуска, а ответы модели между запусками могут отличаться (в одном из прогонов на вопрос про Талиму она отвечала верно), поэтому при повторном запуске `Task4/make_dialogs.py` разметка может измениться. В них ответ в базе есть, но модель его не нашла: про тело Талимы после смерти и про то, кто вырастил детей Корвина Арсеновича. В первом случае нужный документ `smert_talimy.md` найден первым, и промах на стороне модели с 2 млрд параметров («тело начинает тлеть» она не сопоставила с вопросом). Во втором нужный документ `gavriy_i_irma.md` в топ-4 не попал, это промах поиска: вопрос не содержит имён Гаврия и Ирмы, а чанки про детей Корвина Арсеновича далеки от него по смыслу.

Файлы:
- [Task4/rag.py](Task4/rag.py) — поиск, промпт (Few-shot, CoT), генерация;
- [Task4/chat.py](Task4/chat.py) — REPL;
- [Task4/make_dialogs.py](Task4/make_dialogs.py) — прогон тестовых вопросов;

## Запуск в Docker

В [docker-compose.yml](docker-compose.yml) два сервиса:
- **`chroma`**: векторная база, официальный образ `chromadb/chroma:1.5.9` (версия совпадает с клиентом в боте). Отдаёт индекс из папки `DB_DIR` (`Task3/chroma_db/` или `Task5/chroma_db/`). Вместо FAISS используется ChromaDB, выбор обоснован в Задании 1;
- **`bot`**: образ из [Dockerfile](Dockerfile) (Python, зависимости, код бота). Стартует после готовности `chroma` и подключается к ней по сети.

Вне контейнеров остаются:
- **LLM** работает в Ollama на хосте, бот обращается к ней по `host.docker.internal:11434`;
- **эмбеддинг-модель** Qwen3-Embedding-0.6B (≈ 1,2 ГБ) скачивается при первом запуске в том `hf_cache`. Пока она качается, в консоли только предупреждение про HF Hub и тишина, нужно подождать; дальше модель берётся из кэша.

### Что нужно перед запуском

1. Запущенный Docker Desktop.
2. Запущенная Ollama с любой скачанной моделью, например `ollama pull gemma4:e2b` (на Apple Silicon можно `gemma4:e2b-mlx`).
3. Файл настроек `.env`:

```bash
cp .env.example .env
```

В `.env` укажите:
- `LLM_MODEL`: имя модели из `ollama list` (без неё бот не запустится и подскажет, что нужно сделать);
- `DB_DIR`: индекс, который отдаёт `chroma` (по умолчанию основной `Task3/chroma_db`);
- `OLLAMA_URL`: адрес Ollama (по умолчанию `http://host.docker.internal:11434`).

Значение, заданное перед командой (`DB_DIR=... docker compose ...`), главнее значения из `.env`.

### Запуск

Сборка образа (из корня проекта):

```bash
docker compose build
```

Бот с основным индексом, все слои защиты включены:

```bash
docker compose run --rm bot
```

Бот с индексом, в который добавлен «злонамеренный» файл, все слои защиты включены:

```bash
DB_DIR=Task5/chroma_db docker compose run --rm bot
```

Тот же индекс без защиты (утечка `swordfish` видна):

```bash
DB_DIR=Task5/chroma_db docker compose run --rm bot --no-protection --max-distance 2
```

Бот запускается именно командой `docker compose run`: у него интерактивный ввод. Через `docker compose up` он тоже стартует, но ввести вопрос будет некуда. Сервис `chroma` поднимается сам. При смене `DB_DIR` он пересоздаётся с другой папкой автоматически.

Выход из бота: пустая строка или `Ctrl-D`. После выхода `chroma` остаётся запущенной; остановить её и удалить контейнеры:

```bash
docker compose down
```

### Опции бота

Всё, что стоит после `bot`, передаётся боту как флаги:

| Флаг | Действие |
|---|---|
| `--no-protection` | выключить все три слоя защиты |
| `--no-pre-prompt` | выключить pre-prompt |
| `--no-filter` | выключить отбрасывание подозрительных чанков |
| `--no-sanitize` | выключить удаление инъекционных фраз |
| `--max-distance X` | порог расстояния для «Я не знаю» (по умолчанию 0.5) |
| `--show-context` | показывать найденные чанки |

Другую модель Ollama можно задать в команде, не меняя `.env`:

```bash
LLM_MODEL=gemma4:e2b docker compose run --rm bot
```
