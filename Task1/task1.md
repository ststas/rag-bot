### Выводы и ограничения таблицы

- Все три модели dense, поэтому их можно сравнивать между собой без поправок на MoE. У Muse Glimmer и Gemma 4 локальное скользящее окно с редкими глобальными слоями, у Qwen 3.8 гибрид Gated DeltaNet и внимания: это снижает расход KV-кэша на длинном контексте.
- Язык документации компании в задании не указан, поэтому языковую поддержку считаем критерием риска, а не требованием: чем шире заявленная поддержка, тем безопаснее выбор. Качество на конкретном языке по заявлениям вендоров не проверить.
- Данные по AA-LCR, Beam128K и AgentDojo взяты из карточки Meta; Qwen3.8 в ней не участвует, и этих тестов для неё нет ни в одной карточке, поэтому указано «нет данных». Окно 128K хватает всем трём моделям: с чанками по 100–300 слов в промпт попадает несколько фрагментов, а не документ целиком.
- AgentDojo проверяет устойчивость агента к вредоносным инструкциям в обрабатываемых данных (prompt injection через инструменты): близко к Заданию 5, но это агентная постановка, а не RAG.
- Отключаемый thinking важен для скорости и цены ответа: рассуждения увеличивают число токенов. У Muse Glimmer его нельзя выключить, только снизить уровень до low.

### Сравнение по бенчмаркам

Для чат-бота по документам выбраны тесты, которые относятся к ответам на вопросы по документам: следование инструкциям, рассуждение и работа с документами и графиками. Тесты CharXiv RQ и OmniDocBench 1.5 оставлены, потому что в базе знаний есть PDF-спецификации (сейчас ≈ 250, объём страниц в каждой неизвестен), их число будет расти, а в них могут быть таблицы, схемы и графики.

| Бенчмарк                          | Что измеряет и зачем нужен                                                                                                                                                 | Qwen3.8-27B | Muse Glimmer-30B | Gemma 4 31B |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- | ---------------- | ----------- |
| IFBench (следование инструкциям)  | точность выполнения проверяемых требований к ответу (формат, ограничения); основа для «отвечай только по контексту», «если ответа нет, скажи не знаю», «укажи источник»    | **79.5**    | 77.0             | 76.0        |
| GPQA Diamond                      | сложные научные вопросы, ответ нельзя найти поиском; способность рассуждать по шагам, нужна для Chain-of-Thought и вопросов, где ответ собирается из нескольких фрагментов | **89.2**    | 83.5             | 85.7        |
| CharXiv RQ (без code interpreter) | рассуждение по графикам и диаграммам из научных статей; нужен, если в документах есть графики и модель читает их как изображения                                           | **83.7**    | 78.8             | 77.7        |
| OmniDocBench 1.5 (выше лучше)     | разбор страниц документов: текст, таблицы, формулы, порядок чтения; нужен, если PDF подаются как изображения страниц, а не как извлечённый текст                           | **91.1**    | 75.8             | 72.5        |

**Соответствие выбора тестов задаче.** Бот должен отвечать на вопросы сотрудников по корпоративной базе знаний (Markdown/MDX, страницы Confluence, PDF-спецификации), опираясь на найденные фрагменты, рассуждать по шагам (Chain-of-Thought), честно отвечать «не знаю» и не поддаваться инструкциям из документов. Выбранные четыре теста покрывают то, что можно проверить по общедоступным данным вендоров для такой задачи: умение выполнять инструкции, рассуждать и понимать документы. Агентные тесты (код, терминал, управление компьютером) задаче не соответствуют и не учитываются.

Ограничение выбора: тестов на верность найденному контексту, галлюцинации и ответ «не знаю» в карточках вендоров нет, поэтому эти свойства по бенчмаркам оценить нельзя. К RAG напрямую относится только IFBench; CharXiv RQ и OmniDocBench 1.5 значимы, только если модель сама читает страницы PDF как изображения (если PDF разбирается отдельным парсером, а в модель идёт текст, они значения не имеют).

Примечания:

- Веса LLM: число параметров × байт на параметр (0.5 для int4, 1 для int8), без KV-кэша. Индекс: по формуле из таблицы, без накладных расходов HNSW и метаданных.
- S и M рассчитаны на int8, L на int4: веса, эмбеддер и KV-кэш помещаются в GPU-память инстанса. Для L в int8 (70–80 ГБ) 96 ГБ не хватает, нужен g6e.12xlarge ($13.12 в час, ≈ $9 578 в месяц). Потеря точности при 4 битах: для Muse-Glimmer-30B карточка указывает 1.0% в среднем по 15 тестам.
- Векторная база (Chroma или FAISS) работает на CPU и в RAM инстанса. По таблице Chroma для 1024-мерных векторов 16 ГБ RAM ≈ 3,6 млн векторов, 32 ГБ ≈ 7,5 млн (для 192 ГиБ данных нет). Не входят в расчёт: трафик, ОС, сервер LLM, приложение бота.
- Диск EBS gp3: $0.0952 за ГБ в месяц (прайс-лист AWS). Размеры 100, 150 и 300 ГБ оценены по весам моделей и рекомендации Chroma (диск не меньше RAM плюс несколько ГБ); локальный NVMe инстанса не учтён.
- M на SageMaker дороже M на EC2 на том же инстансе: $3.13 против $2.327 в час (+35%, сравнение двух прайсов). В документации AWS эндпоинты названы «полностью управляемыми» («fully managed»), а автомасштабирование «динамически изменяет число инстансов, выделенных для модели, в ответ на изменения рабочей нагрузки» («dynamically adjusts the number of instances provisioned for a model in response to changes in your workload») ([Real-time inference](https://docs.aws.amazon.com/sagemaker/latest/dg/realtime-endpoints.html), [Automatic scaling](https://docs.aws.amazon.com/sagemaker/latest/dg/endpoint-auto-scaling.html)). Что надбавка является платой за управление, это наш вывод. Время добавления инстанса в документации не указано.
- Нагрузка в задании не указана, стоимость в расчёте на запросы или токены не считается.

Рекомендации:

- **Конфигурация.** Вариант M на EC2 (`g6e.xlarge`, Франкфурт), ≈ $1 713 в месяц. Вариант S (≈ $744) возможен как пилот при условии, что качество будет проверено. SageMaker имеет смысл, только если у команды нет ресурсов на сопровождение инфраструктуры.
- **LLM.** Локальная модель класса 27–33B (Qwen3.8-27B, Muse-Glimmer-30B, gemma-4-31B-it): данные остаются в аккаунте компании (раздел 5); по собранным данным модели одного уровня, конкретную выбираем при построении бота.

- **Для кого и зачем.** Заказчик — QuantumForge Software: сократить время поиска информации и нагрузку на старших разработчиков и поддержку, упростить подготовку к SOC 2. Пользователи — разработчики, поддержка, менеджеры и аналитики, новые сотрудники.
